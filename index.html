        Section 00

        全局交付铁律 Global Delivery Laws · 必须遵守

        01

        统一前缀（防冲突）

        中餐厅 yyzct_ · 便利店 yybld_ · 试吃包 yybldty_。所有文件名、Blockbench 内部 Geometry Name、动画 Key 必须带前缀。

        02

        纯小写无空格

        禁止大写字母、中文、空格、特殊符号及 _v2 / _final 等临时尾缀。

        03

        贴图尺寸规范

        必须是 2 的次方：16/32/64/128/256/512（模型贴图常用 64×64 或 128×128）。2D 物品图标统一 64×64。

        04

        UV 边缘留白（防黑缝）

        UV 块与贴图边缘之间必须留出 1~2 像素空隙，禁止贴边，防止游戏内出现黑边黑缝。

        05

        贴图透明度二值化

        透明度只能是 0（完全透明）或 255（完全不透明），严禁出现 1~254 的半透明羽化像素，防止光影反光死黑。

        06

        Blockbench 导出设置

        格式选 Bedrock Model，版本 1.12.0；Geometry Name 必须填 geometry.<前缀><名字>，严禁保留默认 custom / unknown。

        07

        第一人称手模防花屏铁律（★64×64 强制）

        第一人称手持模型（_hand）贴图尺寸必须强制为 64×64，且手臂 UV 严格保持原版不动！严禁使用 16×16 或 32×32，否则游戏内原版手臂材质采样越界溢出，导致严重花屏杂色与贴图错乱。

        美术骨骼制作规范（★关键：直接影响程序渲染控制器控制）

        • 食材骨骼拆分铁律（扁平化无子骨骼）：食材必须按吃掉的顺序拆分为 eat1、eat2、eat3、eat4 …（全小写）。
        • 核心避坑：每一口的所有肉块方块（cubes），必须直接放在 eatN 骨骼本身里面。
        • 严禁嵌套子骨骼：不要在 eat1 下面再建 rou1、rou2、wanzi 等子骨骼——底层渲染控制器显隐不会继承给子骨骼，嵌套会导致程序必须额外写几十行配置去单独隐藏每一块肉。
        • 餐具与筷子骨骼固定命名：盘子/碗底骨骼统一命名 plate 或 bowl；第一人称手模筷子骨骼固定命名 kz（或 kz1、kz2）；第一人称手臂骨骼命名 arm 或 rightArm。

        交付清单

        美术制作要点（标准骨骼层级）

        root
└── waist
    ├── arm           (右手臂，必须全小写拼写为 arm)
    └── food / drink  (食物或饮料骨骼)

        第一人称手模防花屏与 UV 制作硬性规范（★核心技术避坑）

        • 花屏拉伸底层原理：渲染控制器（food_arm_<N>）将假手臂绑定到玩家默认皮肤（Texture.default，固定为 64×64 像素），手臂骨骼使用原版硬编码 UV；当手模工程贴图为 16×16 或 32×32 时，引擎计算采样点 uv * 64 / texture_width 发生 4 倍或 2 倍越界溢出，导致手臂呈现严重拉伸杂色与贴图错乱（花屏）。
        • 铁律一：工程画布强制 64×64：Blockbench 工程创建贴图及导出时，分辨率必须锁定为 64×64，模型 JSON 必须输出 "texture_width": 64, "texture_height": 64。
        • 铁律二：手臂 UV 严禁挪动：手臂骨骼（arm）的 UV 选区必须严格保留在 64×64 画布的原版手臂对应位置，绝对禁止缩放、挪动或重新拆分。
        • 铁律三：低分辨率食品像素摆放：若食品需呈现 16×16 复古像素风，应在 64×64 画布的空白区域绘制，或将 16×16 贴图无损放大至 64×64 画布内，严禁直接缩小整个工程画布尺寸。

        Section 02

        动画制作专属规范 Animation Spec · 打关键帧与命名

        A

        动画文件命名与内部 Key 格式

        项目格式示例
        动画文件名<ns>_<名称>_<类型>.animation.jsonyyzct_hongshaorou_hand.animation.json · yybld_kele_hand.animation.json
        内部 Key 格式animation.<ns>_<名称>_<类型>.<动作>animation.yyzct_hongshaorou_hand.eat
        B

        手持即食类动画（单文件必须集齐五件套）

        饮料 / 雪糕 / 烤肠

        说明单个 .animation.json 内必须包含以下 5 个动作。

        动作名含义要求
        first_hold第一人称手持待机姿态勾选 Loop 循环
        first_scale从物品栏切出时的放大举起补间补间动作
        idle常态呼吸微动勾选 Loop 循环
        take收回 / 切换物品时的动作抬手收物
        eat / drink长按食用 / 畅饮动作不循环，时长建议 1.2s ~ 1.5s
        C

        摆盘菜品夹菜进食动画

        • 动作名：eat。
        • 动作内容：第一人称下筷子夹菜送入口中的完整动作。
        • 关键约束：时长建议在 1.2s ~ 1.6s 之间。
        D

        主食（米饭类）进食重播动画 · 防闪烁铁律

        • 第 0 帧必须做位姿复位：动作的第 0 帧必须打上完整的旋转和位移关键帧，禁止首帧留空，否则长按启动瞬间会闪现默认 T-Pose 姿势。
        E

        第三人称双手端托动画 · 防滑步铁律

        • 动作名：idle（双手合抱平托，勾选 Loop 循环）。
        • 仅手臂打帧：只给 leftArm 和 rightArm 打端托旋转关键帧。
        • 绝对禁止给腿部打帧：严禁给 leftLeg 和 rightLeg 打任何关键帧——腿部由原版行走控制，打帧会导致玩家走路滑步、无法跑跳。
